## 3. Newman-ийн ажиллуулалтууд

| Ажиллуулалт | Файл | Assertions executed | Assertions failed | Exit code |
| --- | --- | --- | --- | --- |
| PASS | results/newman-pass.txt | 22 | 0 | 0 |
| FAIL | results/newman-fail.txt | 22 | 1 | 1 |
| DOWN | results/newman-down.txt | 22 | 22 | 1 |

Collection-д нийт 10 бие даасан тест, 22 assertion байгаа.

- PASS: бүх oracle хангагдсан тул exit code 0.
- FAIL: `lab05-collection-fail.json`-д 1-р тестийн статусыг 201-ийн оронд 200 гэж зориуд буруу болгосон. Ингэснээр 1 assertion унаж exit code 1 болсон. Үүнийг CI quality gate-д ашигладаг: exit code 0 биш бол build унана.
- DOWN: сервер унтарсан үед ECONNREFUSED гарсан. Энэ бол интерфейсийн алдаа (сервертэй холбогдож чадаагүй), харин FAIL бол oracle-ийн алдаа (сервер хариу өгсөн боловч хариу нь хүлээснээс өөр байсан).

## 4. Дүгнэлт

Дизайны 5 алхмаас хамгийн их бодол шаардсан нь сонголтуудыг олох алхам байлаа, учир нь POST /registrations функц дөрвөн оролтын хүчин зүйлээс (оюутан, оюутны үзсэн хичээл, хичээл, урьдач нөхцөл) хамаардаг гэдгийг эхлээд ялган харах хэрэгтэй болсон. Төлөөлөх утга сонгох нь харьцангуй амар боловч урьдач нөхцөлийн "зарим нь үзсэн" гэсэн ангийг ялгаж авахгүй бол 6-р тест мартагдах байсан. Боломжгүй хослол таарсан: байхгүй оюутанд "үзсэн хичээл" гэсэн сонголт утгагүй, мөн байхгүй хичээлд урьдач нөхцөл гэж байхгүй. Тиймээс бүх хослолыг бүтэн үржүүлэхгүй, зөвхөн утга бүхий хослолыг сонгосон. Давхар алдааны тестүүдээс (7, 8) сервер эхлээд оюутныг, дараа нь хичээлийг шалгадаг гэдэг нь харагдсан, өөрөөр хэлбэл хүлээгдэх утга шалгалтын дарааллаас хамаарна. Тест бүрийг бие даасан болгохын тулд тест бүр өөрийн setup болон өөр ID ашигласан, ингэснээр тестийн дараалал солигдсон ч, дахин ажиллуулсан ч үр дүн өөрчлөгдөхгүй. Сервер in-memory тул registrationID хуримтлагддаг, тиймээс би яг утгыг нь биш зөвхөн тоо мөн эсэхийг шалгасан. Тестүүд серверийн код дээр согог олсонгүй, бүх 22 assertion спецификацийн дагуу давсан. Харин код уншихад нэг оюутныг нэг хичээлд давхар бүртгэхийг сервер хориглодоггүй нь анзаарагдсан, гэвч би үүнийг тестлээгүй тул нэмэлт тест болгож болох юм. FAIL ажиллуулалт нь oracle буруу үед exit code 1 болдгийг, DOWN ажиллуулалт нь сервер унтарсан үед ECONNREFUSED гардгийг харуулсан бөгөөд эдгээр нь өөр төрлийн алдаа юм.
